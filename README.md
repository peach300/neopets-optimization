# Neopets userscripts

Userscripts for [Neopets](https://www.neopets.com), written for Tampermonkey.
Mostly display and convenience: live countdowns the site does not show, state
the site forgets between page loads, and cosmetic restyles of the H5 themes.

## Installing

Each script carries `@downloadURL` and `@updateURL`, so Tampermonkey checks for
updates on its own and offers any version newer than the one installed.

Click a script's **Install** link below and Tampermonkey will prompt you.

| Script | Install | What it does |
|---|---|---|
| Daily Timers | [install](https://raw.githubusercontent.com/peach300/neopets-optimization/main/Neopets%20Daily%20Timers.user.js) | One panel on every page with a live countdown per timed activity: interval cooldowns measured from your visit, daily rows that count to midnight NST, fixed-hour windows, and per-day allowances. Settings page to switch any of them on or off, with per-activity alert bells, as one list you can drag into whatever order you want — the panel follows it. Detects a visit from the page's own result text, its own request, or a click, best source first, and says which it used. Grave Danger, the one activity that prints how long is left, is read off the page instead: the row shows the real time remaining rather than the four hours that is only the earliest an adventure could end. Allowance rows (Coconut Shy, Bagatelle, Cork Gun) say Ready until the handler's own answer says you are out — "No more throws, you've had yer lot." — rather than printing a tally of clicks that was wrong in both directions. The Symol Hole, which needs a window published daily on Jellyneo before it means anything, links there from the row instead of printing "set". Display only. |
| Dice-A-Roo and Scorchy Slots Refresher | [install](https://raw.githubusercontent.com/peach300/neopets-optimization/main/Neopets%20Dice-A-Roo%20and%20Scorchy%20Slots%20Refresher.user.js) | Plays Dice-A-Roo or Scorchy Slots for the pet-boredom mechanic and stops itself when the page says the pet is bored. **It acts for you**: a reload turned out not to start a game, so each play submits the game's own form and spends the game's own money - 5 NP per Dice-A-Roo game, whose rolls are then free, and 5 NP per Scorchy Slots spin. It is meant to look like holding F5 down - a round is four to eight plays as real page loads about 150-400ms apart, then a pause of 1-6s (12-15s one round in eight), then another round. A round cannot be a loop, because each play replaces the document that would run it, so the plays still owed are written to the store and the next page load picks the round up and carries on. Runs on `dicearoo.phtml`, `play_dicearoo.phtml` and `slots.phtml` and nowhere else. Dice-A-Roo stays on the roll page: its "Roll Again" is free and keeps the pot, so a game is one 5 NP charge and then rolls until it ends. Only Game Over is a dead end - that page carries no form at all - and the run re-enters by building the start request itself, so the click-to-play page never comes back on screen. The site's token is required on every one of those posts, so the walk back to the landing page survives only as the fallback for not having one. The "Stop playing and collect N NP" form is deliberately never sent: banking a pot is a decision about your Neopoints. Scorchy Slots carries its reels form in every answer, so it just keeps posting that. Each game is keyed on its form's hidden field or action URL rather than the button's label, since those differ ("Lets Play!" against "Click Here to Play") and matching one silently ignored the other game. `BACKGROUND_PLAYS: true` instead sends the plays as requests without leaving the page: about 30 plays a minute against this path's 20, measured live, but the page never moves and a working run is then indistinguishable from a broken one, which is why it is not the default. That path paints each answer into the page and recovers a failed send by asking the game page what the server now thinks, rather than re-sending a request that may already have landed. No cap on plays and none on time: a run goes until the pet is bored, until something unfamiliar comes back, until the rate says a bug is looping, or until you click Stop. Both caps were guesses at a number nobody has measured - 194 live Scorchy Slots plays did not reach boredom - and a cap that lands first ends the run short of the only thing it is for. The cost: a game whose boredom wording the script has never matched has nothing else stopping it, and Scorchy Slots is that game at 5 NP a play. `MAX_REFRESHES` and `MAX_MINUTES` take a number again whenever you want one. Starts stopped, and Stop is a pause: the plays stay counted and the button reads Resume, since boredom takes a few hundred plays and stopping to read something should not throw away how far the run has got. The only thing that resets the count is a run that reached the boredom line - that one is over, so the Start button greys out and reads Done, and clears itself back to Start once the game's own page stops carrying the bored line. The wait between rounds is a bar that drains rather than a number counting down; the seconds are still there as its tooltip. Inside a round nothing is drawn in it — the gaps are a sixth of a second and a bar that fast is a flicker — but the empty track keeps its place so the panel never changes height. The header's run light flashes once per play. |

Appearance only. |
| Lottery Ticket Autobuy | [install](https://raw.githubusercontent.com/peach300/neopets-optimization/main/Neopets%20Lottery%20Ticket%20Autobuy.user.js) | **It acts for you**: it submits the lottery's own form and spends your Neopoints. Fills the lottery ticket with six unique random numbers and, once you press Start, buys ticket after ticket until the day's twenty are gone — walking back to the ticket page between buys. Twenty is the lottery's own limit per account per day, not a setting, so it is a constant in the file rather than a dial. 20 NP a ticket, 400 for a full day. Same control as the Refresher: Start, Stop (a pause — the day's count is kept, and the button then reads Resume), and a greyed-out Done once the twenty are spent. Guards: the day's count held against the NST date so a reload cannot buy past it, a short wait before every single buy with Stop live throughout — drawn as a draining bar, the Refresher's, which shows the pause between buys too — one submit per page load, and it fires only on a page that actually has the buy form. Starts stopped; the boxes are filled on every load either way. |

| Wishing Well | [install](https://raw.githubusercontent.com/peach300/neopets-optimization/main/Neopets%20Wishing%20Well.user.js) | **It acts for you**: it submits the well's own form and spends 22 NP a wish. Wishes for an item the well has actually granted lately — read off the page's own "wishes granted" table, drawn uniformly over the raw rows so an item listed seven times is seven times as likely, which is the only evidence anyone outside TNT has about what the well currently wants. Seven wishes per twelve-hour window, and the page's own "Wish Count: N" overrules this script's count wherever it can be read. Same control as the Refresher: Start, Stop (a pause), Resume, and a greyed-out Done once the window is spent; a short wait before every wish with Stop live throughout, drawn as the same draining bar. `SUBMIT_WISHES: false` falls back to filling the form and leaving the click to you. Starts stopped. A restyled fork of [Auto-Wisher](https://greasyfork.org/en/scripts/532440) by @dogwithglasses (MIT), whose item pool is the idea worth keeping. |

## Conventions

Every script is named `# Neopets <Thing>`. Tampermonkey sorts its list by name
and `#` sorts ahead of letters, so the prefix keeps them together at the top of
the dashboard. The prefix is in `@name` only — filenames are unprefixed.

Tampermonkey identifies an installed script by `@namespace` + `@name`, so a
rename installs as a new entry rather than updating the old one. If you have an
older copy of any of these under its unprefixed name, delete it after
installing, or both copies run at once.

Each file carries far more prose than code, on purpose: a `WHY` block saying
what the site actually does and what was measured to find that out, a `SCOPE`
note on what the script does not do, and comments on any constant that was
arrived at rather than chosen.
